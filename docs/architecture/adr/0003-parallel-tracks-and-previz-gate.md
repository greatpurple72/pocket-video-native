# ADR-0003 — 双轨并行 + PrevizGate 效果审核闸门

- 状态:已采纳(Accepted)
- 日期:2026-06-19

## 背景
用户要求:① 手感优先,但 SLG 大循环要同时制作;② 每个模块实际制作前先出效果图/视频审核。

## 决策 1 — 双轨并行
- **Track A(主轴)**:实时 11v11 比赛手感。
- **Track B(并行)**:SLG 大循环元层(俱乐部/球员/经济/联赛),先以占位数据驱动开发,待比赛可玩后接入。
- 两轨通过 MatchLayer↔MetaLayer 的明确接口(赛前阵容输入 / 赛后结果输出)解耦,可独立推进。

## 决策 2 — PrevizGate(效果审核闸门)
- 任何模块进入**实际制作前**,必须先产出并经用户审核通过:
  1. 设计规格(`module-spec`);
  2. 视觉效果图 / UI 线框 / 分镜(storyboard);
  3. previz 效果视频。
- 通过后记入 `progress/STATE.md` 的 PrevizGate 段,再开始制作。
- 流程与产出形态见 `_templates/previz-gate.md`。

## 现实约束(效果视频如何产出)
- 云端会话无法渲染真实 UE 视频。故:
  - 静态效果图 / 线框:云端产出(SVG/HTML/Markdown)+ 给用户 AI 绘图工具的提示词;
  - 真实引擎效果:**灰盒 previz**——云端写可运行占位场景,用户本地跑并录屏审核。

## 权衡
- PrevizGate 增加前置成本,放慢"立即写代码"的速度。但显著降低"做错方向返工"风险,符合单人+AI 的高返工成本现实。

## 影响
- ROADMAP 每个 Phase 的闸门均含"PrevizGate 通过"。
