## 1. 愿景与北极星(不缩水的最终目标)

一款**跨平台(PC/手游/后续主机)足球题材 SLG**:
- **前期玩法**:类 eFootball 的**实时可控 3D 比赛**(你亲手踢)。
- **后期玩法**:融合无尽冬日 / Last War / Kingshot 的 SLG 元循环——**俱乐部帝国养成 + 联盟(联赛/足协)PvP + 跨服 + 活动运营**。
- **核心差异化**:把"**你能亲手踢的实时 3D 比赛**"做成 SLG 的战斗结算层——这是所有头部 SLG 都没有的钩子。

## 2. 残酷的现实约束(必须先对齐)

> 这一节决定了整份计划是"可执行的"还是"幻想"。请务必认同后再批准。

**资源现实**:开发力量 = 你 1 人 + Claude Code,1 台机器。
**对标现实**:eFootball 背后是 Konami 数百人 + 数十年体育游戏积累;无尽冬日/Kingshot 背后是 Century Games 数百人 + 工业化买量/运营/服务器中台。

**结论**:我们**无法在合理时间内 1:1 复刻**这些产品的完成度。但我们**完全可以**:
1. 做出一个**有独特乐趣的垂直切片(vertical slice)**:证明"亲手踢的比赛 + 俱乐部养成"这个核心融合是好玩的;
2. 用**原型优先(prototype-first)**逐步扩展,每一步都有**能跑起来、能上手玩**的产物;
3. 把"上线全球商业化 SLG"作为**北极星**,而不是第一年的交付目标。

**因此本计划的策略三原则:**
- **Prototype-first**:先做能玩的最小核心,不做框架空壳。
- **Vertical slice over breadth**:先把"一场比赛 + 一点养成"打磨好,而不是先铺一堆半成品系统。
- **Fun-gate**:每个阶段有明确的"好玩验收点",不好玩就停下来调,而不是继续堆量。

## 3. 产品融合设计(本项目的核心创新)

把足球与 SLG 的系统做**结构映射**,让两套玩法共用一套养成经济:

| SLG 经典系统 | 本项目的足球化映射 |
|---|---|
| 主城/基地建造 | **俱乐部基地**:球场、训练中心、青训营、医疗室、商业区 |
| 英雄收集/抽卡 | **球员收集**(= eFootball Dream Team gacha):球员即英雄 |
| 练兵/升级 | **球员训练/成长**:体能、技术、战术熟练度 |
| 资源(粮/铁/金) | **资金 / 训练点 / 转会点 / 声望** |
| 战斗结算(自动) | **★实时 3D 比赛(你亲手踢)★** —— 差异化核心 |
| 联盟 | **足协 / 联赛俱乐部联盟**:共享、互助、联赛对抗 |
| 联盟战 / 跨服 | **跨服联赛 / 杯赛 / 德比对抗 + 升降级** |
| 限时活动 | **赛季、转会窗、点球大战活动、传奇球员复刻** |
| 买量小游戏 | **点球/任意球/过人/射门 timing 爽点小游戏**(hybrid-casual 钩子) |

**核心循环(玩家每日)**:
打比赛(实时操作)→ 赢资源/球员碎片 → 养成球员 + 升级俱乐部 → 阵容更强 → 打更高级别比赛/联赛 PvP → 联盟协作与对抗 → 赛季结算与活动。

## 4. 技术架构(分层,逐步建设)

```
┌─────────────────────────────────────────────┐
│  客户端 (Unreal Engine 5, C++ / Blueprint)     │
│  - 比赛模块: 球员控制器/球物理/动画/比赛AI/裁判规则 │
│  - 元游戏模块: 俱乐部/养成/抽卡/UI(UMG)/联赛   │
│  - 输入抽象层: 手柄(全手动) + 触屏(智能辅助)  │
│  - 平台层: PC(Win) 首发, Android 次之, 主机后置 │
└─────────────────────────────────────────────┘
                 │  (后期)
┌─────────────────────────────────────────────┐
│  在线服务 (后期才上, 先用单机/本地存档)          │
│  - 账号/存档/经济校验 (服务器权威)              │
│  - 异步 PvP(先) → 实时 PvP(后, UE5 replication) │
│  - 联盟/联赛/活动配置 (live-ops 配置化)         │
└─────────────────────────────────────────────┘
```

**关键技术决策:**
- **比赛先单机 vs AI**:最难、最差异化、最能验证乐趣的部分先做,且无需服务器。
- **PvP 演进路线**:本地 vs AI → 异步 PvP(对方阵容数据 + AI 代打)→ 实时联机 PvP(最后,网络同步是公认难点)。
- **数据驱动**:球员属性、养成曲线、经济数值全部走 DataTable/配置表,便于 AI 辅助快速迭代平衡。
- **存档先本地**:早期用本地 SaveGame,把后端推迟到玩法被验证之后,避免过早投入服务器复杂度。

## 5. 分阶段路线图(每阶段都有"能玩"的交付物)

> 不用绝对日历(单人节奏波动大),用**里程碑 + 验收标准**。每阶段结束你都能上手玩。

### Phase 0 — 地基与可玩的"球+人"(Walking Skeleton)
**目标**:UE5 工程跑起来,一个球员能在球场上跑动、带球、射门,球有基本物理。
- 交付物:UE5 项目骨架(Git + 规范)、一块球场、1 个可控球员、球的物理、基础摄像机。
- 验收(Fun-gate):**用手柄/键盘能带球跑动并把球射进空门,手感不别扭。**
- 风险点:UE5 学习曲线、球物理手感。这是整个项目"是否值得继续"的第一个生死验收。

### Phase 1 — 一场能踢的比赛(核心垂直切片)
**目标**:11v11(或先 5v5)一场完整比赛,有队友/对手 AI、传球、射门、进球、基本规则(界外/进球/简单越位可后置)。
- 交付物:比赛流程(开球→进行→进球→结束)、队友与对手 AI(站位/抢断/跑位)、传球与射门机制、比分与计时、智能辅助传球(触屏友好)。
- 验收(Fun-gate):**一局比赛踢下来是"想再来一局"的,而不是机械的。**
- 这是**整个项目最重要的里程碑**——比赛不好玩,后面的 SLG 都无意义。

### Phase 2 — 球员养成 + 俱乐部(SLG 元层 v1,单机)
**目标**:比赛之外有"养成闭环":赢比赛得资源 → 抽/养球员 → 阵容变强 → 影响比赛表现。
- 交付物:球员数据系统(属性/位置/稀有度)、抽卡(Dream Team 式)、球员训练/升级、俱乐部基地(几个可升级建筑)、阵容编辑、主菜单/UI(UMG)、本地存档。
- 验收:**"打比赛→变强→打更强比赛"的核心循环成立,养成对比赛有可感知影响。**

### Phase 3 — 单人战役 + 生涯 + Hybrid-casual 钩子
**目标**:有内容可玩 1~2 小时;并做出可独立分发的**买量小游戏**(点球/任意球/过人挑战)。
- 交付物:生涯/赛季模式(对 AI 联赛、升降级)、剧情化引导(Last War 式漏斗:小游戏→深度)、点球大战等爽点小游戏、首充/任务/每日活动(单机版)。
- 验收:**新玩家 30 分钟留存得住;小游戏单独拎出来也好玩(买量素材潜力)。**

### Phase 4 — 平台化与移动端
**目标**:PC 打包 + Android 包,触屏操作完善,性能可接受。
- 交付物:Windows 打包、Android 打包与触屏 UI/智能辅助、画质分级、输入抽象统一(手柄/触屏/键鼠)。
- 验收:**手机上能流畅踢一局,触屏手感可接受。**

### Phase 5 — 在线化与 SLG 长线(后端启动)
**目标**:账号/存档上云,异步 PvP,联盟/联赛雏形,服务器权威经济。
- 交付物:后端(账号/存档/经济校验)、异步 PvP(打对手阵容的 AI 代打)、联盟系统、跨服联赛雏形、活动配置化(live-ops)。
- 验收:**两个玩家能异步对战并影响排名;经济不可被本地篡改。**
- 说明:这一阶段是从"单机原型"跨入"真·SLG 运营产品"的分水岭,工作量最大,建议玩法被充分验证后再启动。

### Phase 6 — 实时 PvP / 主机 / 商业化打磨(北极星阶段)
- 实时联机 PvP(UE5 replication / 必要时回滚同步)、主机移植(手柄已先行,移植成本可控)、深度商业化(VIP/赛季通行证/转会窗活动)、反作弊、数据驱动运营。

## 6. 从今天开始的具体执行步骤(批准后立即执行)

**Step 1 — 决策与环境(Phase 0 起点)**
1. 确认本机已安装 **UE5**(版本建议 5.4+)、Visual Studio(C++)、Git LFS(大资源)。
2. 在本仓库新建 `/game` 子目录或**独立新仓库**放 UE5 工程(UE 工程体积大,建议独立仓库 + Git LFS)。→ **需要你确认:同仓库还是新仓库?**
3. 建立工程规范:命名、目录结构、`.gitignore`(UE 模板)、Git LFS 跟踪 `*.uasset *.umap`。

**Step 2 — Walking Skeleton(Phase 0)**
4. 创建 UE5 C++ 工程(Third Person 模板起步),一块测试球场,导入/做一个占位球员与球。
5. 实现球的基础物理 + 球员带球 + 射门到空门。
6. **第一个 Fun-gate 验收**:你上手试,确认手感方向对。

**Step 3 — 迭代节奏(贯穿全程)**
7. 每个里程碑:我先写**该阶段的详细技术设计 + 任务拆解(TDD)**给你过目 → 实现 → 你上手玩并给反馈 → 调整 → 提交。
8. 数值/配置走表格化,方便快速调平衡。

> ⚠️ 关于"单机协作"的现实提醒:我(Claude Code)能写 C++/蓝图逻辑、系统设计、数值配置、文档与脚本;但**UE 编辑器内的可视化操作(摆场景、连蓝图、调材质、试手感)、美术资源、以及"这局好不好玩"的主观判断需要你来做**。我们是"我写系统骨架 + 你在编辑器里组装和体感调优"的分工。3D 美术/动画资源建议用 UE 商城/Mixamo/Fab 现成资源起步,不自制。
