## 1. 愿景与北极星(不缩水的最终目标)

一款**跨平台(PC/手游/后续主机)足球题材 SLG**:
- **前期玩法**:类 eFootball 的**实时可控 3D 比赛**(你亲手踢)。
- **后期玩法**:融合无尽冬日 / Last War / Kingshot 的 SLG 元循环——**俱乐部帝国养成 + 联盟(联赛/足协)PvP + 跨服 + 活动运营**。
- **核心差异化**:把"**你能亲手踢的实时 3D 比赛**"做成 SLG 的战斗结算层——这是所有头部 SLG 都没有的钩子。

## 2. 残酷的现实约束(必须先对齐)

> 这一节决定了整份计划是"可执行的"还是"幻想"。请务必认同后再批准。

**资源现实**:开发力量 = 你 1 人 + Claude Code,1 台机器。
**对标现实**:eFootball 背后是 Konami 数百人 + 数十年体育游戏积累;无尽冬日/Kingshot 背后是 Century Games 数百人 + 工业化买量/运营/服务器中台。

**结论**:我们**无法在合理时间内 1:1 复刻**这些产品的完成度。但我们**完全可以**:
1. 做出一个**有独特乐趣的垂直切片(vertical slice)**:证明"亲手踢的比赛 + 俱乐部养成"这个核心融合是好玩的;
2. 用**原型优先(prototype-first)**逐步扩展,每一步都有**能跑起来、能上手玩**的产物;
3. 把"上线全球商业化 SLG"作为**北极星**,而不是第一年的交付目标。

**因此本计划的策略三原则:**
- **Prototype-first**:先做能玩的最小核心,不做框架空壳。
- **Vertical slice over breadth**:先把"一场比赛 + 一点养成"打磨好,而不是先铺一堆半成品系统。
- **Fun-gate**:每个阶段有明确的"好玩验收点",不好玩就停下来调,而不是继续堆量。

## 3. 产品融合设计(本项目的核心创新)

把足球与 SLG 的系统做**结构映射**,让两套玩法共用一套养成经济:

| SLG 经典系统 | 本项目的足球化映射 |
|---|---|
| 主城/基地建造 | **俱乐部基地**:球场、训练中心、青训营、医疗室、商业区 |
| 英雄收集/抽卡 | **球员收集**(= eFootball Dream Team gacha):球员即英雄 |
| 练兵/升级 | **球员训练/成长**:体能、技术、战术熟练度 |
| 资源(粮/铁/金) | **资金 / 训练点 / 转会点 / 声望** |
| 战斗结算(自动) | **★实时 3D 比赛(你亲手踢)★** —— 差异化核心 |
| 联盟 | **足协 / 联赛俱乐部联盟**:共享、互助、联赛对抗 |
| 联盟战 / 跨服 | **跨服联赛 / 杯赛 / 德比对抗 + 升降级** |
| 限时活动 | **赛季、转会窗、点球大战活动、传奇球员复刻** |
| 买量小游戏 | **点球/任意球/过人/射门 timing 爽点小游戏**(hybrid-casual 钩子) |

**核心循环(玩家每日)**:
打比赛(实时操作)→ 赢资源/球员碎片 → 养成球员 + 升级俱乐部 → 阵容更强 → 打更高级别比赛/联赛 PvP → 联盟协作与对抗 → 赛季结算与活动。

## 4. 技术架构(分层,逐步建设)

```
┌─────────────────────────────────────────────┐
│  客户端 (Unreal Engine 5, C++ / Blueprint)     │
│  - 比赛模块: 球员控制器/球物理/动画/比赛AI/裁判规则 │
│  - 元游戏模块: 俱乐部/养成/抽卡/UI(UMG)/联赛   │
│  - 输入抽象层: 手柄(全手动) + 触屏(智能辅助)  │
│  - 平台层: PC(Win) 首发, Android 次之, 主机后置 │
└─────────────────────────────────────────────┘
                 │  (后期)
┌─────────────────────────────────────────────┐
│  在线服务 (后期才上, 先用单机/本地存档)          │
│  - 账号/存档/经济校验 (服务器权威)              │
│  - 异步 PvP(先) → 实时 PvP(后, UE5 replication) │
│  - 联盟/联赛/活动配置 (live-ops 配置化)         │
└─────────────────────────────────────────────┘
```

**关键技术决策:**
- **比赛先单机 vs AI**:最难、最差异化、最能验证乐趣的部分先做,且无需服务器。
- **PvP 演进路线**:本地 vs AI → 异步 PvP(对方阵容数据 + AI 代打)→ 实时联机 PvP(最后,网络同步是公认难点)。
- **数据驱动**:球员属性、养成曲线、经济数值全部走 DataTable/配置表,便于 AI 辅助快速迭代平衡。
- **存档先本地**:早期用本地 SaveGame,把后端推迟到玩法被验证之后,避免过早投入服务器复杂度。

## 5. 分阶段路线图(双轨并行,每阶段都"能玩")

> 完整可维护版见 **`docs/progress/ROADMAP.md`**(当前位置实时标注)。本节为概览。
> 用**里程碑 + 验收闸门**,不用绝对日历。**每个模块进入制作前先过 PrevizGate(效果图/视频审核)。**

**双轨说明**:
- **Track A(主轴)= 比赛手感**:Phase 0→1 死磕实时 **标准 11v11**。
- **Track B(并行)= SLG 大循环**:与 A 同步搭建俱乐部/球员/经济/联赛的单机元层,先用占位数据驱动,待比赛可玩后接入。
- 两轨通过 MatchLayer↔MetaLayer 接口(赛前阵容输入 / 赛后结果输出)解耦,可独立推进。

| Phase | Track A 比赛 | Track B SLG | 验收闸门 |
|---|---|---|---|
| **0 走骨架** | UE5 工程、球场、可控 Footballer、球物理、带球射空门 | 元层数据骨架(球员属性表、Club 存档结构、主菜单壳) | PrevizGate + 手感方向对 |
| **1 标准比赛 ★** | **标准 11v11**、队友/对手 AI、传/射/抢断、规则、SmartAssist | 赛后结算→资源→养成→影响下场 | PrevizGate + "想再来一局" |
| **2 元层 v1** | 手感打磨 | 俱乐部建筑、Signing 抽卡、训练升级、阵容编辑、UMG、本地存档 | "打比赛→变强→打更强"闭环成立 |
| **3 生涯+钩子** | 生涯/联赛(对 AI)、升降级 | 引导漏斗、HookMinigame、单机首充/每日 | 30 分钟留存 + 小游戏单独好玩 |
| **4 平台化** | 性能/输入抽象 | 触屏 UI/SmartAssist | 手机流畅踢一局 |
| **5 在线化** | 异步 PvP | 后端账号/存档/经济校验、Alliance、跨服 League、活动配置化 | 异步对战影响排名 + 经济防篡改 |
| **6 北极星** | 实时 PvP(replication/回滚)、主机移植 | 深度商业化(VIP/通行证/转会窗)、反作弊、数据运营 | — |

> Phase 1 是**全项目最重要里程碑**——比赛不好玩,后面 SLG 都无意义。
